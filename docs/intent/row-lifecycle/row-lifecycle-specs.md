# Row Lifecycle — EARS Specs

"The `_id` invariant" below is the one the [PortaBase format specification](../../wiki/format.md) states for the `_data` view: `_id` values are unique and consecutive from 0 through one less than the row count. `portabase check` reports a file that violates it as CHK-DATA-003. The ROW-DB specs below also hold on a file whose `_id` values are unique but have gaps. They promise nothing about a file holding duplicate `_id` values.

## ROW-DB (row identity and `Database` row mutation)

- [x] **ROW-DB-001**: When a row is added to a `_data` view that satisfies the `_id` invariant and holds n rows, the system shall assign the new row `_id` n.
- [x] **ROW-DB-002**: When a row is added to a `_data` view whose `_id` values are unique but not consecutive (gaps, such as IDs 74 through 98 in a 25-row file), the system shall assign the new row an `_id` one greater than the largest `_id` present in `_data`, so that the new row's `_id` is held by no other row.
- [x] **ROW-DB-003**: When `Database::addRow` adds a row, the system shall return an empty error message and report the new row's `_id` through the row-ID out-parameter.
- [x] **ROW-DB-004**: If the number of values passed to `Database::addRow` differs from the number of columns, then the system shall reject the row with an error message listing the excess values or the missing columns.
- [x] **ROW-DB-005**: If a value passed to `Database::addRow` is not valid for its column's type, then the system shall reject the row with an error message naming that column — except that, where the caller requested CSV blank-number substitution, a blank integer or decimal value is replaced by the column's default instead.
- [x] **ROW-DB-006**: If `Database::addRow` rejects a row for any reason, then the system shall leave the file exactly as it was before the call — no row appended to `_data`, no Sequence column's stored next value advanced, and no enum option added — and shall leave the row-ID out-parameter unwritten.
- [x] **ROW-DB-007**: When `Database::addRow` adds a row with generated sequence values (as it does for rows added or copied from the row editor), the system shall store each Sequence column's stored next value (the column's `_cdefault`, set through `Database::setDefault`) in the new row and advance that stored value by one, independently of the row's `_id`.
- [x] **ROW-DB-008**: When `Database::addRow` adds a row, the system shall write each value under every `_data` property the format specification defines for its column's type: a decimal or calculation value as both a float and the string entered, an enum value as both its option text and its option index, and an image value as its format string, together with the image bytes when the value names an image file to import. A row added from the row editor gets its image bytes afterwards (ROW-UI-004).
- [x] **ROW-DB-009**: When a single row is deleted with renumbering requested (`Database::deleteRow` with `compressRowIds` true), the system shall remove the row whose `_id` matches and decrement by one the `_id` of every row whose `_id` is greater, so that a `_data` view satisfying the `_id` invariant before the deletion still satisfies it afterwards.
- [x] **ROW-DB-010**: If `Database::deleteRow` is asked to delete an `_id` that no row in `_data` holds, then the system shall leave every row of `_data`, every `_id`, and the `_id` the next added row will receive all unchanged.
- [x] **ROW-DB-011**: When a batch of rows is deleted with per-row renumbering suppressed and `Database::compressRowIds` is then called, the system shall renumber the surviving rows' `_id` values to 0 through one less than the surviving row count, preserving their relative order, and the next row added shall receive `_id` equal to the surviving row count. This holds whether the `_id` values had gaps before the batch or not, so a bulk delete leaves a file with gaps satisfying the `_id` invariant.
- [x] **ROW-DB-012**: If `View::deleteAllRows` is called on a view whose filter matches no rows, then the system shall leave every row of `_data` and every `_id` unchanged, including on a file whose `_id` values have gaps.

## ROW-UI (Row menu actions, row editor, display refresh)

- [x] **ROW-UI-001**: When the user chooses Row ▸ Add, the system shall open the row editor with each field showing its column's default value.
- [x] **ROW-UI-002**: When the user chooses Row ▸ Copy with a row selected, the system shall open the row editor pre-filled with the selected row's values and, on accept, add the edited values as a new row — with its own `_id` and freshly allocated Sequence values — leaving the selected row unchanged.
- [ ] **ROW-UI-003**: When the user accepts a copied row without changing an image field that holds an image in the source row, the system shall store the source row's image data (format string and image bytes) in the new row.
- [x] **ROW-UI-004**: When the user accepts the row editor while adding or copying a row and an image field was set in the dialog, the system shall write that image's bytes to the newly added row.
- [x] **ROW-UI-005**: If the user accepts the row editor while adding or copying a row and an integer, decimal, or time field holds an invalid value, then the system shall show a warning naming the field and re-show the dialog with the entered values intact, without adding a row.
- [ ] **ROW-UI-006**: If `Database::addRow` rejects the row the row editor is committing as an addition or copy, then the system shall show the rejection message and re-show the dialog with the entered values intact, writing no image data, refreshing no display, and leaving the file's edited state unchanged.
- [x] **ROW-UI-007**: When the user cancels the row editor while adding or copying a row, the system shall add no row and leave the file's edited state unchanged.
- [x] **ROW-UI-008**: When a row added or copied from the row editor passes the current view's filter, the system shall update the display so that the current page shows exactly the rows the current filter, sorting, and pagination place on it, including the new row if it falls there.
- [x] **ROW-UI-009**: When a row added or copied from the row editor fails the current view's filter, the system shall store the row and leave the display unchanged, showing no notification.
- [x] **ROW-UI-010**: When a row is added or copied from the row editor, the system shall mark the file as edited without writing it to disk.
